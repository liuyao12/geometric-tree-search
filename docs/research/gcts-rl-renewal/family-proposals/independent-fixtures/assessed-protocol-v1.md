# Source-only automatic family proposal assessment

The proposed first implementation is a fixed pre-search family proposal pool.
It keeps the original \(171\)-body authority immutable and preserves the
complete \(229\)-recipe, \(217\)-formula, \(24\)-row primitive graph. No new
mathematical proof, proposal count, model construction or search has been
performed in this assessment.

The accepted lifecycle controller compiles and freezes its descriptor tuple
at the root. Its checkpoints bind those descriptor identities. A runtime
insertion or deletion would therefore need a new trailed pool protocol or a
separately justified deterministic reconstruction at every node. Root-fixed
generation permits reuse of the checked waiting, ready, consumed and retired
hint states, whole revalidation, forced-first resynchronization and paired
rollback. The smaller first bridge is a composition compilation wrapper,
not a mutation of that controller or its point graph.

The original authority omits conclusion fields when constructing its body
records. The compact projection retains each declared conclusion row and
formula code. A new interface adapter must check the complete projection
digest already bound by the body, then bind that declared conclusion to an
actual primitive member and its output code. The adapter cannot infer it by
body name or a convention that the final member proves the requested goal.

## Complete bounded proposal grammar

Visit every registered family type and every ordered pair of registered types,
including repetitions: \(171\) singles and \(171^2=29\,241\) pairs. These
are finite type-domain sizes, not measured numbers of bindings or proposals.
Every first component's ordered premise occurrence binds to an actual selected
initial placement with exactly the required formula code. Every second
component's premise occurrence binds either to such an initial placement or
to the first component's declared conclusion member, with at least one
conclusion-to-receptor link. Enumerate the entire formula-filtered Cartesian
binding domain in a declared stable order. Preserve repeated equal bindings
and each source/read-port occurrence. No empty-row marking supplies an anchor.

The first component's output may be pending when the composite is proposed.
It is then an explicitly included primitive source-body obligation, not a new
assumption or an established proof. The whole primitive certificate must
eventually close it from the original hypotheses. Binding a later input to
it is structurally conditional, and never licenses pruning or graph degrees.

For each binding, use one declared canonical increasing row embedding. Process
components in their ordered sequence and source members in their registered
order. Resolve every ordered source reference. Reuse the earliest already
assigned primitive placement with the identical recipe and ordered references
only if its row is strictly after all references and the preceding member of
this component. Otherwise assign the earliest unused in-bound row strictly
after those rows. Preserve every source occurrence's mapping; a later source
occurrence inside a component cannot merge into an earlier member. Any missing
reference, row exhaustion, member collision, capacity or marking disagreement
rejects only that proposed embedding. The generator visits all bindings;
there is no guessed winning subset or target-row placement preference.

This grammar is deliberately limited to one canonical embedding and at most
two components. It is complete for that frozen proposal grammar, not for all
increasing embeddings, source combinations or mathematical proofs. Rebased
proof members have regenerated signed-offset markings; the family embedding
is a checked proof-DAG transport, not one rigid translation of an atomic macro.
The primitive placements retain translation-only orientation.

## One whole composition hint

Register a validated component pair as one whole union hint. Two independent
component hints would allow the second to remain preferred after the first's
promised output becomes unavailable, and would not implement whole-composition
retirement. A new proposal-authority wrapper should reconstruct each component
with the original authority's `expected` and `compile`, check the declared
output-to-input edges and canonical embedding, retain all ordered component
and receptor provenance, then form the distinct-member occupancy sum and the
compatible marking union. Exact full decorated primitive identities may be
shared across components; formula equality alone may not share occupancy.

The wrapper exposes the `graph_text`, `epoch`, `check_graph` and `compile`
boundary consumed by the existing controller. Its separate immutable proposal
epoch binds the grammar, original authority, complete pool and wrapper source.
It returns the existing `CompiledDescriptor` interface; the descriptor relation
is an automatically generated finite primitive composition proposal. It is
not a newly admitted lemma, a native-accepted interface or an activation of
transported authority in the native engine. This wrapper is currently only
an API proposal and requires its own source/actual independent gates.

The complete graph still decides global dead ends, forced moves and the
earliest generation. Only then may a ready whole hint prefer one eligible
primitive member. After every primitive selection, return to global checks.
Emit all remaining legal base candidates exactly once. Hint absence,
retirement, proposal preparation limits or conditional outputs do not remove
base alternatives. Unknown children restore the paired state without exclusion;
only completely exhausted children authorize their parent-local exclusion.

## Prospective producer and comparison

A future source freeze should keep the current original \(56\)-input body
authority plan, old point-plan epoch, all broader prerequisites and raw source
closures. It should check all \(171\) interface projections, enumerate the
complete declared single/pair binding grammar, validate canonical embeddings,
compile the complete immutable proposal tuple, and freeze it before either
search. There is no slot-language widening or new geometric symbol rule.

Compare the unchanged fixed-forward literal-receptor control with that same
ordering preceded by validated fixed family preferences. Proposed family
priority is decreasing distinct primitive member count, followed by canonical
source-interface/binding bytes; it uses neither the target nor a winning word.
The common fallback remains the full unchanged primitive permutation. This
would test authored generic construction and fixed selection of reusable
families, not RL training. A learned selector should be a later experiment
with actual update evidence, equal proposal availability, frozen training and
evaluation tasks and reward charged in unique primitive placements and cost.

Before running, freeze separate preparation and search ceilings. Suggested
first resource envelope: the existing \(180/175/170\)-second outer/supervisor/
child gates and \(512\,\mathrm{MiB}\) peak ceiling, with a \(30\)-second
preparation deadline; each of two search controls keeps \(128\) attempts,
\(20\) seconds and \(2\,000\) events. In-flight overhead and serialization
remain covered by the outer gate. If complete preparation is not obtained,
do not search from an undocumented partial pool. Preserve the preparation
unknown and exact visited counts. A pool-size guard may abort preparation,
but must never silently retain a top subset. No prospective resource figure
is a measured feasibility result.

The costs include interface decoding and validation, every type and binding
visit, embedding, joint marking construction, sharing checks, descriptor
compilation, all whole-hint scans and rollback, fallback ordering, both searches,
serialization, watchdog sampling and reaping, plus the independent audit.
Original inventory admission, failed native/resource gates, previous control
experiments and model warmup remain separate disclosed prior costs.

## Required next gates and open claims

ROOT's design decision precedes larger implementation. Then freeze a source
successor implementing the generic generator and composition wrapper, exact
input and preservation closure, independent prospective reconstruction and
adversarial controls. Required controls include duplicate premise ports,
noninjective equal/unequal codes, same-formula different-key sharing, altered
valid members with fresh self-hashes, stale authority, forward/cyclic edges,
wrong declared conclusions, within-body occurrence merging, whole-composition
retirement, forced interruption, paired rollback and unknown versus exhausted
children. None has been executed for this proposed protocol.

An actual search result must undergo independent complete-domain, ordering,
transaction and source-body/group reconstruction. A point solution additionally
requires every primitive logical line and the exact original ground sequent
to be checked; selected output constraints and a valid proposal are not proofs.
The literal formula-color graph remains a finite symbolic grammar. Encoding
the independently accepted primitive request on the shared request-independent
native FOL-machine Wang palette is a separate gate, as are aggregate/native/
compiler preservation and any general transport theorem.
