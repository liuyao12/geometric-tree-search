Which fields may the search change?

The input constructor receives the fixed checker program, known axioms, known goal and a byte capacity. It does not receive a proof syntax tree. Each proof byte has the full byte domain; all links, private markers and known data are fixed. The parser inside the machine reads these bytes and builds the proof's terms, formulas and inference lines.

Known and read onlyProof byte choicePrivate structural marker

Every byte domain is \(\{0,\ldots,255\}\). Its data word has exactly eight binary cells, least significant bit first. Nil and pair identifiers retain their longer canonical words. Return addresses use a separate, unchanged encoding.

These controls fill the unknown fields with authored examples to test the machinery. A search must choose those fields itself before a proof can be called discovered.

How far does the tape-to-tiles bridge reach?


The physical representation keeps read-only headers, linked structure and markers fixed. A binary transport cell carries one of two complete symbol-code words. Its file bits cannot be chosen independently. Tamper controls check the whole header, length, alphabet and fixed symbols.


The generic lowering diagnostic covers the machine's instruction operations, nested calls and live return frames. A small physical machine control does not establish a complete physical execution of the much larger proof checker. Construction limits and execution limits are reported separately.

The intended advantage remains an experimental question. A single proof machine and reusable checked lemma families make a common foundation possible. They do not by themselves establish that GCTS or RL finds proofs faster. The baseline must receive the same theorem inventory, resource bounds and checking standard.


Arithmetic and Hilbert-style geometry will share the logical machinery and differ in their explicit axiom data. Geometry statements remain symbolic: the spatial arrangement of computation tiles carries no implicit assumption about points, lines or diagrams.


The complete point-frontier contract still applies to a future GCTS engine: all candidate dependencies, global dead ends and forced moves, earliest-generation branching and exact rollback. The present diagnostic is a compiler and checking experiment.
