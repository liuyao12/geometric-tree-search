Why CALL needs particular care

Same mathematical value, different storage identifier

Program metadata and captured argument lists also occupy the canonical heap. Later mathematical values can therefore receive different numeric identifiers. The proposed correspondence must preserve values structurally:

\[e(a)=a\quad(0\leq a\leq256),\qquad e(\operatorname{pair}(x,y))=\operatorname{pair}'(e(x),e(y)).\]

The map must preserve both children of every pair and the complete register and call-frame state. Canonical pair construction may reuse a node already created for metadata without changing its value. This is a proposed simulation invariant and an explicit proof obligation; it is not yet a verified equivalence theorem.

The input domain also matters: native string encoding with surrogate preservation and normalization by a raw JSON parser need a separate correspondence argument. A certificate is checked relative to its declared theory; arithmetic or Hilbert-geometry claims still require the exact licensed axioms, symbolic signature and public goal.

Acceptance, resource costs and failure statuses need separate arguments. Extra heap nodes cost space and work. The older generic interpreter can also raise when execution falls off its code, whereas the proposed physical machine takes a nonaccepting exit. No equality of those statuses or costs is claimed.
