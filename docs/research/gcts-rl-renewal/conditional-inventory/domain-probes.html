Assessment

Both methods prove the direct instance of the supplied arithmetic axiom. This is a basic universal-instantiation control, not a new arithmetic theorem. The harder congruence consequence and the incidence statement return bounded search UNKNOWN for both methods.

These observations establish no GCTS advantage. The point method solves no additional target, and its successful search takes more marginal time here. The methods count different primitive units, so their attempt counts are not interchangeable. There is no comparison with an external automated theorem prover in this experiment.

The incidence statement uses a supplied closed uniqueness licence and five hypotheses. It tests symbolic application of that licence; it does not derive the licence from a full Hilbert axiom system. All symbols are formal. No geometric picture, metric calculation, point/line sort system or Euclidean construction enters checking.

UNKNOWN means that the current bounded search returned no proof candidate. It does not establish falsehood, unprovability or an encoding impossibility. All three original targets and their original row bounds are retained; there are no retries or easier replacements.

Whole experiment cost

Each cold job includes controls, compilation, the complete point-model reference checks, certified marking construction, both searches, final proof checks, output and custody. Compilation and point setup are shared by the two methods. The arm times are marginal; they are not standalone cold solver times. Nested clocks must not be added.

The large shared model/reference setup dominates these small searches. The present implementation does not yet provide practical proof-search performance. Each actual kept the original limits: 160 seconds of cooperative work, 180 seconds to positive child completion, 210 seconds of custody, 225-second external fallback, 1 GiB conservative whole memory, and 128 MiB physical output. Each search allows 600 attempts and a cooperative two-second budget.
