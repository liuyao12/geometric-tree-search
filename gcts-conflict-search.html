Geometric tree search / The nine-cube certificate

A standalone research prototype

The search now learns its own conflicts.

A new C++ engine reproduces the nine-cube two-corona impossibility result. It owns the point–candidate graph, assignment trail, conflict analysis, backjumps, restarts and proof writer. Search calls no external SAT solver.

What this establishes. Conflict learning can run in our own finite point–candidate search. This is a GCTS/CDCL prototype: it does not yet implement the full reference GCTS propagation order, synthesize geometric markings, or demonstrate a speedup over Glucose.

How a failed branch changes the next search

01 · PROPAGATEUpdate every affected point.Coverage, overlap and learned constraints force placements or exclude candidates. Each implication retains its reason.
02 · EXPLAINResolve the conflict.First-UIP analysis traces the contradiction through its reasons and derives a constraint justified by the original problem.
03 · BACKJUMPUndo irrelevant decisions.Restore candidate counts, coverage and activation triggers. The new constraint immediately forces an assignment.
04 · BRANCHReturn to the frontier.After propagation finishes, choose an earliest-generation point. Degree breaks point ties; conflict activity ranks its candidates.

The learned constraints can refer to selected and excluded placements. They keep the assumptions of this fixed root and two-corona problem. They are not automatically reusable exclusions elsewhere in space.

What was checked

  • The generated formula matches the existing certificate byte for byte: 8,140 placements and 569,020 constraints.
  • 150 small conditional-target problems match exhaustive enumeration, with full graph audits at branches and rollbacks.
  • All 47 small UNSAT proofs pass DRAT-trim. An additional pigeonhole test verifies learning through restarts and constraint deletion.
  • The unit-cube positive control passes an independent voxel and two-corona replay.
  • The complete nine-cube proof passes DRAT-trim; its LRAT conversion passes cake_lpr.

Where it differs from reference GCTS

The model has 1,700 potentially required lattice points. Root-halo points are always required; a selected root neighbor activates its own halo. All target obligations have fixed generation zero in this finite experiment.

Within propagation, implications run in CDCL watch order. A distant dead point can be discovered after another implication is queued. The strict GCTS rule that global dead points take precedence over each individual forced placement remains to be implemented.

There are no learned point-value markings, fractional capacities, unbounded growth generations or RL proposals. The learned clauses are supplementary proved constraints, fed back into the candidate graph.

Run the search, or check its proof

The implementation and geometry encoder need a C++17 compiler and Python 3.9+ standard library. DRAT-trim is only used to check the output. The published download is a trimmed binary DRAT proof, about 36 MB compressed.

Run a fresh search

python3 scripts/gcts-conflict-search/run.py \
  --output /tmp/gcts-nine --seconds 300 \
  --drat-trim /path/to/drat-trim

Verify without rerunning search

python3 scripts/gcts-conflict-search/verify.py \
  --output /tmp/gcts-proof-check \
  --drat-trim /path/to/drat-trim

Run from a checkout of this repository. A time limit returns “unknown” unless search has completed. Its partial proof is never presented as an impossibility certificate. Full reproduction needs several GB of temporary disk space.

Credit and next step

The conflict-learning design draws on the CDCL tradition, including Glucose by Gilles Audemard and Laurent Simon and MiniSat. This implementation links neither solver. The earlier published certificate was generated by a modified Glucose solver and retains that attribution.

The next experiment is to make point conflicts and forced placements drive propagation in the reference GCTS order, while preserving these explanations and independently checkable proofs. Then scheduler and learning choices can be compared on the same candidate graph.
