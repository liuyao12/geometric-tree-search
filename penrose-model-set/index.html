How to use the marking controls

Run pauses at frontier corona 3, then continues the same search to 5, 7, and onward. As in the turtle demo, a tile’s generation is one plus the earliest generation incident at its vertices (the seed is 0); the displayed corona is the minimum generation at an unfinished point with 0 < t < 1. Branch ordering is reproducible and continues unchanged between milestones. Internal safety limits prevent unbounded runs.

Intermediate dots use exact rational subdivisions in ℚ(ζ₅), with 4, 8 or 16 steps per original stripe length. They are inspection samples, not an enumeration of all cyclotomic integer points. The solver still checks whole segments between dots.

Extent adds the selected multiple of each stripe’s original length at both ends. Dashed lines show extensions. At zero, the original edge-port rule is recovered. In Ammann mode, changing extent restarts the search. In edge-arrow mode it changes only the drawing.

For each direction, m = 1 on its bar and extension, m = 0 elsewhere inside the tile, and m is undefined outside that component’s support. An extension reaching a neighboring tile must meet its corresponding bar, even without a shared edge. Different directions are separate components. The inspector uses — for undefined components. The t-value remains the summed corner weights divided by ten; stripe and extension endpoints outside vertex support have t = 0.

With “Enforce Ammann bars” off, the search explicitly checks the Penrose edge arrows: single/double arrow type and direction must agree along each shared edge. With it on, the search checks only the complete Ammann markings, without calling the edge-arrow predicate. Matching bars enforce the same local edge compatibility.

“Show edge arrows” / “Show Ammann bars,” direction highlighting, colors and line weight change only the drawing. All five Ammann directions are always enforced in bar mode, including gray directions. The 1- and 3-direction options highlight those families in the fixed cyclotomic frame; they do not weaken the rule.

Both searches check exact polygon non-overlap, corner capacity and a single outer boundary, with genuine backtracking and no window oracle. At extent zero the two modes have the same search path. Positive extent adds overlap constraints that can prune earlier; geometric checking costs may offset the reduction in proposals. A finite patch or a budget stop does not establish infinite extendibility.

The thick and thin rhombs each carry a fixed arrow template and a complete fixed five-stripe template. The solver finds compatible rigid orientations; these may resolve differently as the search extends or backtracks. Neither mode accepts arbitrary unmarked rhomb tilings.
