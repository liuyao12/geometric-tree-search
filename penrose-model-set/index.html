How to use the marking controls

The hover inspector reports the current placed patch. Here t is the sum of stored corner weights divided by ten (a full vertex has t = 1); at bar endpoints outside that vertex support, t = 0. The marking m is a five-vector of stripe-end counts by direction at each exact port. Matching tiles agree on m; their values are not added. At vertices outside the marking support, m is undefined. Vertex coordinates lie in ℤ[ζ₅]; decoration ports can have rational denominators in ℚ(ζ₅).

With “Enforce Ammann bars” off, the search explicitly checks the Penrose edge arrows: single/double arrow type and direction must agree along each shared edge. With it on, the search checks only the complete Ammann markings, without calling the edge-arrow predicate. Matching bars enforce the same local edge compatibility.

“Show edge arrows” / “Show Ammann bars,” direction highlighting, colors and line weight change only the drawing. All five Ammann directions are always enforced in bar mode, including gray directions. The 1- and 3-direction options highlight those families in the fixed cyclotomic frame; they do not weaken the rule.

Both searches check exact polygon non-overlap, corner capacity and a single outer boundary, with genuine backtracking and no window oracle. The two complete local rules accept the same shared-edge orientations, so the same seed and proposal order give the same search path. Computation costs may differ. A finite patch or a budget stop does not establish infinite extendibility.

The thick and thin rhombs each carry a fixed arrow template and a complete fixed five-stripe template. The solver finds compatible rigid orientations; these may resolve differently as the search extends or backtracks. Neither mode accepts arbitrary unmarked rhomb tilings.
